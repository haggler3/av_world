av_world · an auto-tagging system for driving scenes, trained on simulator truth

Scene Auto-Tagger

Rules can find a hard brake; nobody can annotate a distracted driver or a road user hidden behind a truck. This simulator knows every hidden trait, can fork the world, and exports real Argoverse 2 logs and simulated runs in one format. So it teaches taggers the hidden things, calibrates them to a precision target, applies them to real logs, and flags where they should not be trusted.

First principles

  1. A tag is a claim about an interval of a scene, made by a tagger, with a confidence. Search, fusion, calibration, review and drift all work on that one record, so it carries its provenance.
  2. Simulator labels have no human noise but a domain gap. So the gap is measured per scene, and sim-trained tags on scenes the simulator could not have made are flagged.
  3. A score is not a probability. Calibration makes it a frequency; a threshold with a precision bound makes it a decision; the uncertain middle goes to a person.
  4. Taggers that agree reveal their accuracy without labels (Dawid–Skene), so taggers can be fused before anyone labels anything.
  5. Human time is the scarce resource. Review what teaches the model most, not what comes first.
  6. Every stage is a pure function of its inputs and config. So the pipeline is a cached DAG, and a change reruns only what depends on it.

The engineering DAG

Eighteen stages, each a pure function with a content-addressed cache: key = sha256(name, config, the inputs’ keys, the function’s source). The full build takes about 11 minutes on 4 cores; a threshold change reruns calibration → tags → store → qa in seconds. av-world tag explain prints which stages are fresh.

key(stage)  = sha256(name, config, [key(d) for d in deps], source of the function)
run(target): for s in topological_order(target):
                 load cache/<s>-<key>.pkl if it exists, else out = s.fn(*[value(d) for d in deps], **config); save it

Pros

  • Only stale stages rerun; results trace to the exact config and code that made them.
  • About 100 lines, no service to run.

Cons

  • Pickles are tied to Python and numpy versions; the cache grows until cleaned.
  • No parallel branches. Each stage already uses all four cores, so this costs little here; on a cluster, Dagster, Airflow or Ray would replace this file.

One scene format and a versioned tag record

sim_scenes · av2_scenes · store
scene = { x, y, yaw, v, alive [vehicles, frames] at 0.2 s; kind, length, av; ego; pedestrians; truth (sim only) }
from_av2: read_av2 → av2_to_scene(every 2nd frame) → dense arrays
from_sim: record the city → every 10 s and AV: vehicles within 80 m → same arrays + hidden truth
Tag = (scene_id, source, name, level, agent, t_start, t_end, confidence, tagger, version, status)

Pros

  • Every tagger runs unchanged on real and simulated data, which is what makes sim-to-real evaluation possible.
  • A flat parquet table scales to millions of tags.

Cons

  • Real logs hold only what the AV perceived; simulated ones see everything.
  • Lanes are not in the format, so lane rules use geometry.
2

Kinematic rules

rules_sim · rules_av2
leader(i, t) = nearest j with x_ij > 0, |y_ij| < 1.8 m, |heading_ij| < 35°  (in i’s frame)
gap = x_ij − (Lᵢ + Lⱼ)/2,   headway = gap / vᵢ,   TTC = gap / (vᵢ − vⱼ) when closing
hard_brake: v drops 4 m/s within 1 s · tailgating: headway < 0.8 s for 1 s · low_ttc: TTC < 1.5 s
cut_in: j becomes i’s leader within 15 m, 2 s after driving parallel in the next lane while i went straight
lane_change: lateral move > threshold in 3 s, heading back within tolerance, small total swing

Pros

  • Transparent and instant, with no training.
  • The same statistics as measured on real logs.

Cons

  • Geometry stands in for lanes: curves made false lane changes until the thresholds were tuned (method 10).
  • Blind to anything hidden.
3

Learned taggers from simulator truth

windows_train · learned_model · learned_scores · hidden_ahead
features(i, t) = (v, a, has_leader, gap, closing speed, leader accel, |yaw rate|, vehicles within 20 m)     trajectories only
window = the last 5 s;  labels at its end:  distracted = dist_t > 0;  tailgater = IDM T < 1.25 s;  crash_soon = crash within 3 s
causal dilated CNN, trained on a separate dense recording, rare positives up-weighted
hidden_ahead = occlusion net N6 from the ego’s seat → P(someone hidden 25 m ahead in the lane)

Pros

  • Produces tags that cannot otherwise exist: nobody can annotate “distracted” or “hidden”.
  • The training recording is independent of the golden set.

Cons

  • Labels are only as realistic as the simulator’s drivers.
  • A state with no 5 s behavioural signature (distraction, crash risk) stays weak, and the scores show it.
4

Calibration, a precision threshold and abstention

calibration
g = isotonic fit of truth on score (pool-adjacent-violators), on held-out calibration copies
t_emit   = min t with WilsonLower95(precision{g(s) ≥ t}) ≥ 0.9     → status "auto"
t_review = min t with WilsonLower95(precision) ≥ 0.5               → status "review" (a person decides)

Pros

  • Calibration error falls by 10–100×.
  • A tagger that cannot reach the target emits nothing rather than garbage.
  • Exactly the uncertain items reach people.

Cons

  • The bound assumes independent items. Frames from one scene are correlated, so it is optimistic: occlusion reached precision 0.85, not 0.9.
  • It covers simulated data only; for real data the domain check has to take over.
5

The domain check: sim_gap

domain
f(scene) = 17 numbers (density, speeds, acceleration spread and tails, pedestrians, rate of each kinematic tag)
z = (f − μ_sim) / σ_sim;   d = mean distance to the 5 nearest simulated scenes;   sim_gap if d > 99th percentile of held-out sim

Pros

  • Marks exactly where sim-trained tags should not be trusted, and says why.
  • Doubles as a to-do list for the simulator.

Cons

  • Depends on the 17 chosen features.
  • A scene can be “inside” on these and still unrealistic in other ways.

Search and similarity

store
query("cut_in & hidden_ahead & !sim_gap") → recursive-descent parser → predicate over a scene’s tag names
--overlap: intersect the positive tags’ intervals in time;  similar(id) = top-k cosine of [features, log(1 + tag counts)]
$ av-world tag query "cut_in & hidden_ahead" --overlap
19 scenes match 'cut_in & hidden_ahead' in av2
  av2:00e988db-…  [3.0-4.0 s] [4.0-5.0 s]
  av2:01d7deae-…  [4.0-5.0 s] [5.0-6.0 s] [3.8-4.0 s]

Pros

  • Boolean queries cover most mining requests.
  • Overlap answers “while”, not just “and”.
  • One example finds more of a rare scene.

Cons

  • The embedding is hand-built; a learned scene encoder would capture interactions.
  • Brute force is fine to about 10⁶ scenes; beyond that it needs an ANN index.
7

Counterfactual tags

counterfactual
from exact forks (other dice fixed): action_sensitive = the AV’s 4 s outcome differs between its 5 actions (3.8 % of moments)
tagger: spread = maxₐ Q(o, a) − minₐ Q(o, a) of the interventional risk critic → AUROC 0.982

Pros

  • A label that exists only because the world can be forked.
  • Marks where the AV’s choice matters: the most valuable moments to train and test on.

Cons

  • Needs the AV’s 28 observation features: simulated runs and stacks that log them, not Argoverse 2.
8

Weak-supervision label model

label_model
votes: hard_brake, low_ttc, tailgating (rules), distracted, crash_soon (learned, top 2 %)
Dawid–Skene EM from the majority vote:  M: aⱼ = Σ qᵢ[vᵢⱼ=1] / Σ qᵢ,  bⱼ = Σ (1−qᵢ)[vᵢⱼ=0] / Σ (1−qᵢ),  π = mean q
                                         E: qᵢ = π Π aⱼ^[v=1](1−aⱼ)^[v=0] / (… + (1−π) Π (1−bⱼ)^[v=1] bⱼ^[v=0])

Pros

  • Fuses taggers without labels.
  • Its accuracy estimates are a free quality report.
  • A new tagger is one more column.

Cons

  • Assumes taggers are independent given the truth; rules sharing gap and speed are not.
  • EM can collapse with rare positives, hence the majority-vote start and the simulator check.
9

Active learning and the review queue

active · store (review_queue)
the simulator answers as reviewer; each round refit the head (logistic on logit + 12 window features)
random: 100 at random · uncertainty: 100 nearest p = 0.5 · unc+div: 500 most uncertain → k-centre greedy picks 100 spread out

Pros

  • Strategies are compared with a perfect reviewer before a person spends any time.
  • Abstained tags are already queued, sorted by uncertainty.

Cons

  • Here the head is too small for review to move it: all strategies end near AUROC 0.57.
  • A real loop needs a review interface and a verdict store (the status field is ready).
10

Golden-set QA, rule tuning and drift

rule_tuning · qa
golden set = an independent simulated recording with exact truth (copies 0–5 tune, 6–7 report)
rule_tuning: grid over lane-change and cut-in thresholds → best F1 on copies 0–5
qa: event precision/recall (overlap ±1 s); AUROC, precision/recall at threshold, ECE before/after; sim_gap share; tag rates real vs sim

Pros

  • Every number on this page is recomputed after any change, against exact labels.
  • Rule thresholds are chosen by data.

Cons

  • The golden set inherits the simulator’s blind spots.
  • Real-data quality still needs a small human-labelled set: what the review queue is for.
